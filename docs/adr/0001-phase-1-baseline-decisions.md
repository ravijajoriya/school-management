# ADR 0001 — Phase 1 baseline decisions

Status: accepted (pending school/developer review) · Date: 2026-11-21

Records where the implementation intentionally differs from, or adds to, the Phase-by-Phase
Developer Flow document.

## Tooling

| Decision                                                                                          | Reason                                                                                                                                              |
| ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vitest instead of Jest; oxlint instead of ESLint                                                  | Defaults generated by NestJS 12 and create-vite 9; one test runner and one linter across the repo.                                                  |
| API on TypeScript 6.0, web on TypeScript 7.0                                                      | NestJS 12 CLI pins `~6.0`; Vite's template uses TS 7. Revisit when Nest supports TS 7.                                                              |
| Prisma pinned to exactly 7.10.1                                                                   | npm `latest` tag of `prisma` points at an 8.0 release candidate.                                                                                    |
| Zod (Standard Schema) for request validation                                                      | NestJS 12 `StandardSchemaValidationPipe` validates Zod schemas and generates OpenAPI from them, so API and web share schemas from `@school/shared`. |
| `@nestjs/observe`, Nest deploy script, and Prisma "agent skills" removed from generated scaffolds | Third-party telemetry / unrequested files.                                                                                                          |
| pnpm `allowBuilds`: only `prisma`, `@prisma/engines`; `@scarf/scarf` denied                       | Supply-chain hygiene; scarf is install telemetry.                                                                                                   |

## Database

| Decision                                                                       | Reason                                                                                                                                                                                               |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary keys default to PostgreSQL 18 `uuidv7()` (doc: `gen_random_uuid()`)    | Time-ordered UUIDs index better. Requires PostgreSQL 18+ in every environment.                                                                                                                       |
| Status columns are `VARCHAR` + `CHECK` constraint, not Postgres enums          | Doc specifies VARCHAR; CHECK enforces allowed values while keeping changes to a simple migration.                                                                                                    |
| `users`: added `must_change_password`, `password_changed_at`                   | Email/SMS are out of scope, so "password reset" = admin reset + forced change on next login (also covers Phase 9 "force first-time password setup"). `password_changed_at` invalidates older tokens. |
| `users`: CHECK at least one of email/phone; email stored lower-case            | Both are nullable in the doc but a user must have a login identifier.                                                                                                                                |
| `refresh_tokens`: added `family_id`, `replaced_by_id`                          | Refresh-token rotation with reuse detection: replaying a rotated token revokes the whole family.                                                                                                     |
| `audit_logs` append-only enforced by DB trigger (UPDATE/DELETE/TRUNCATE raise) | Doc: "Append-only; restrict update/delete."                                                                                                                                                          |
